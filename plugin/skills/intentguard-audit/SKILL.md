# IntentGuard로 웹사이트 검사하기

IntentGuard는 다른 AI 에이전트에게 브라우저로 일을 시키고, **그 에이전트의 말이 아니라 같은 브라우저의 마지막 상태로** 코드가 채점한다.
너의 역할은 검사를 준비하고 실행하고 결과를 정확히 전하는 것이다. **판정을 직접 내리거나 바꾸지 않는다.**

## 1. 준비 확인

- IntentGuard 저장소 루트에서 실행한다(`src/audit/cli.ts`가 있는 곳). 없으면 사용자에게 저장소 위치를 묻는다. 남의 저장소에 설치하지 않는다.
- 처음 한 번 필요한 것: `pnpm install`, `pnpm exec playwright install chromium`, 로그인된 Antigravity CLI(`agy`).
- 로그인이 필요한 화면, CAPTCHA, 자동 브라우저를 막는 사이트는 검사할 수 없다. 차단을 우회하지 않는다.

## 2. 검사 조건 정하기

사용자에게서 세 가지를 받는다. 빠진 것이 있으면 추측하지 말고 묻는다.

| 항목 | 규칙 |
| --- | --- |
| 주소 | `http` 또는 `https` 주소 |
| 시킬 일 | 사용자가 에이전트에게 할 말 그대로. 정답 경로(어느 버튼을 누를지)는 넣지 않는다 |
| 성공 기준 | 일이 끝나면 화면에 **문구 전체가 그대로** 보여야 할 글자. 여러 개면 `--expect`를 반복한다 |

성공 기준 문구를 고를 때:
- 버튼·링크·메뉴·입력칸의 글자, 다른 문장의 일부, 숨은 글자는 채점기가 인정하지 않는다. 결과로 **새로 나타나는 본문 글자**를 고른다.
- 시작 화면에 이미 보이는 문구면 검사기가 실행을 거부한다. 다른 문구를 고른다.
- 저장되는 일(추가, 수정, 설정)은 `--persist`를 붙여 새로고침 뒤에도 남는지 본다. 열기·찾기처럼 저장이 없는 일은 붙이지 않는다.
- 기준을 정하려고 사이트를 직접 열어 보는 것은 괜찮지만, **시킬 일을 네가 대신 해 보지 않는다.**

서버 데이터를 바꾸는 과제는 사용자가 **본인 소유의 테스트 환경**이라고 말했을 때만 `--allow-writes`를 붙인다. 기본은 쓰기 요청을 막는다.

## 3. 실행

`audit_site` MCP 도구가 연결돼 있으면 그것을 쓴다. 같은 검사기를 부르고, 판정·채점 근거·볼 곳·증거 경로를 정해진 형식으로 돌려준다. 없으면 아래 CLI를 쓴다.

```bash
pnpm exec tsx src/audit/cli.ts --url '<주소>' --task '<시킬 일>' --expect '<문구>' [--expect '<문구>'] [--persist] [--model <모델>]
```

- 기본 모델은 `gemini-3.8-flash-low`. 여러 모델은 `--model a,b,c`, 반복은 `--repeat N`. 쓸 수 있는 모델은 `agy models`로 본다.
- 실행 1회에 1~4분 걸리고 사용자의 Antigravity 사용량을 쓴다. 여러 모델·반복은 사용자가 원할 때만 한다.
- 인자는 작은따옴표로 감싸고, 값 안의 작은따옴표는 빼거나 바꾼다.
- `--dangerously-skip-permissions`를 쓰거나 사용자의 전역 agy 설정을 바꾸지 않는다.

## 4. 결과 읽기

터미널 마지막 줄의 `리포트:` 경로에서 `report.md`를 읽는다. 같은 폴더에 실행마다 `.json`(채점 근거·조작 기록·에이전트의 답), `.png`(끝난 순간의 화면)가 있다.

| 판정 | 뜻 |
| --- | --- |
| `confirmed-success` | 기준을 채웠고 에이전트도 확인했다고 보고 |
| `unconfirmed-success` | 기준은 채웠지만 에이전트는 확인 못 했다고 보고 |
| `false-failure` | 실제로는 됐는데 에이전트는 실패라고 보고 |
| `false-success` | 에이전트는 됐다고 했지만 기준을 못 채움. 가장 위험하다 |
| `failure` | 기준을 못 채웠고 에이전트도 실패를 인정 |
| `invalid` | 한도·연결 오류 등으로 검사가 성립하지 않음. 사이트의 실패로 세지 않고 다시 돌린다 |

## 5. 보고

다음 순서로 짧게 전한다.

1. **판정**과 그 뜻, 모델 이름
2. **채점 근거**: 충족·미충족 기준과 이유(`grade.checks`, `grade.notes`)
3. **막힌 곳**: `issues`의 종류와 횟수. `click-blocked`(가려진 버튼), `target-not-found`, `ambiguous-target`, `disabled-control`은 화면 쪽 단서다. `agent-misuse`는 에이전트의 도구 사용 실수라 사이트 문제로 말하지 않는다
4. **증거 위치**: `report.md`, 실행별 `.json`, `.png` 경로
5. 실패했다면 **성공 기준이 맞았는지**를 먼저 짚는다. 마지막 화면에서 일이 끝나 있는데 기준 문구가 달랐다면 기준을 고쳐 다시 검사하자고 제안한다

지키는 것:
- 에이전트의 답(`RESULT` 표식)을 채점 결과보다 믿지 않는다. 판정은 검사기의 것을 그대로 쓴다.
- 1회 결과로 성공률이나 모델 순위를 말하지 않는다.
- 막힌 곳은 원인의 확정이 아니라 확인할 단서로 전한다.
- 실패를 다시 돌려 좋은 결과로 덮지 않는다. 다시 돌렸다면 두 결과를 모두 보고한다.

## 화면으로 하고 싶을 때

같은 검사를 입력부터 재검사 비교까지 화면에서 하려면 `pnpm exec tsx src/app/main.ts`를 실행하고 `http://127.0.0.1:4717`을 연다.
